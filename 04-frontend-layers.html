Chapter 04 · ~12 minutes

The frontend, layer by layer.

The pattern that 80% of TAP•IP code follows. Click each layer to see what it owns.

Frontend code is where most of TAP•IP lives. When a user clicks a button, here's the chain of code that fires — top to bottom.

01Browser — React component

The page the user sees. A React component that renders HTML and listens for clicks. When the user clicks "Save", the component calls a server action — a special TypeScript function marked 'use server'.

Lives in: frontend/src/app/[tenantSegment]/(authenticated)/engine/patents/page.tsx (or similar).

Does NOT: talk directly to the database. It talks to a server action, which talks to a repository, which talks to the database.

02Server action — 'use server'

A function marked 'use server' at the top. Next.js wires this up so when the browser calls it, the function runs on the server (not in the browser). It's a magic drive-through window.

Lives in: frontend/src/app/actions/patents.ts (one file per domain).

Always wrapped in tenantAction() — the wrapper is the security boundary. It auto-checks auth, extracts the tenant, and builds the TenantContext for you.

frontend/src/app/actions/patents.ts (simplified) 'use server'; export const createPatent = tenantAction(async (ctx, input) => { // ctx is the TenantContext { tenantId, userId, role } // — the wrapper already verified auth and tenant. await requireFeature(FEATURES.IPMS_PATENTS); await requirePermission(PERMISSIONS.PATENT_CREATE); const repo = new PatentRepository(ctx); const patent = await repo.create({ ...input, tenantId: ctx.tenantId }); revalidatePath(engineRoutes.patents(ctx.tenantId)); return patent; });
03Repository — PatentRepository

A TypeScript class that owns all database queries for one entity. PatentRepository owns every read and write related to patents. MatterRepository owns matters. There are 60+ repositories in frontend/src/lib/repositories/.

If you want anything related to patents — list them, create one, update a status — you call a method on PatentRepository. Nothing else writes patent SQL.

A repository is a single specialist desk for one form. Want anything related to patents? Go to the Patent desk. They know the forms, the filing rules, the right cabinet. Nobody else handles patent forms — there's one source of truth.
04TenantContext — the compiler's guard rail

TenantContext is a TypeScript type — a branded type — that means: this code has been verified to be scoped to one specific tenant.

A TenantContext can't be passed to code expecting a different context type (like ServiceContext or PublicContext). The TypeScript compiler refuses to compile mismatches. This is structural security — the compiler enforces what humans would otherwise have to remember.

TenantContext is a hall pass with your name printed on it. The compiler refuses to let a "tenant user" hall pass into rooms marked "service-only." Forged passes don't compile.
