The platform: how it all runs.

Python backend + the four services that keep TAP•IP running. You'll see these names every day.

The Python backend.

99% of user traffic goes through Next.js. The other 1% goes through a separate Python server (FastAPI). The Python server exists for work that doesn't fit nicely in TypeScript:

  • AI agents. Long-running, tool-using AI workflows (think: "draft this patent claim, check for prior art, summarize the response"). Python's AI ecosystem (LangChain, Anthropic SDK with tools) is much more mature than TypeScript's.
  • Heavy math. The Cost Engine and the Deadline Engine — both crunch a lot of numbers across rate cards and jurisdiction rules.
  • Scheduled jobs (cron). Daily docketing checks, weekly reports, monthly billing runs. Lives in backend/scripts/ + a Celery worker.
  • Document RAG. A separate microservice for "ask a question about a patent PDF" at backend/document_rag/.

The Python backend uses async SQLAlchemy to talk to the same Postgres database. Same tenant isolation guarantees as the frontend.

Async SQLAlchemy is like ordering coffee while the previous person's drink is being made. The waiter doesn't stand still — they take the next order while the espresso machine runs.

You won't write Python this summer unless we explicitly assign it. But know the backend exists, runs at port 8001, and handles the "AI / math / cron" cases. The frontend calls it via HTTP for those specific jobs.

🐳 Docker.

Docker packages software into a "container" — a sealed bundle that runs identically on the founder's laptop, on a teammate's laptop, and on Railway's servers. Inside the container is the app code, its dependencies, and the right version of Node or Python.

Docker is a shipping container for software. Whatever code you put inside, it travels the same way and arrives identical. No "works on my machine" problems.

🐙 GitHub.

GitHub hosts the source code. Every change is tracked. Multiple people can work on the same project without overwriting each other. You'll open Pull Requests here when you make changes — that's how the founder reviews your work before it goes live.

GitHub is a shared Google Doc for code. Every change is tracked, everyone can see history, you can fork your own copy. Pull Requests = "I want to merge my edits into the main doc."

🟩 Supabase.

Supabase rents us a managed Postgres database. They handle the server, backups, security patches. We just connect and run queries. They also give us a free authentication system (login + signup + password reset) and a dashboard called Supabase Studio where you can browse rows.

Supabase is renting a Postgres database instead of running your own. Like Vercel for databases — they handle the server, backups, and access control; we just connect.

🚂 Railway.

Railway runs our Docker containers in the cloud. When we push code to GitHub, Railway automatically detects the push, builds a new Docker container, and rolls it out to live servers. Five Railway services keep TAP•IP running: the marketing site (tap-ip.com), the Next.js app, the Python backend, a Celery worker, and the RAG microservice.

Railway is the company that picks up your shipping containers from GitHub and runs them on its trucks (servers). Auto-deploys when you push code.
For your own product

GitHub: free for public repos, $4/mo for private. Supabase: free for 500MB / 50K users. Railway: $5/mo free credit. Docker: free.

Total cost to run a real product on this stack at small scale: $0/month. That's not marketing. That's what most indie hackers actually pay until they hit traction.
